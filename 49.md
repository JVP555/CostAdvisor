# What shipped since last Friday (Aug 29 → Sep 4)

A presentation script — not a code changelog. Each section says **what to click**, **what you'll see**, and **why it matters**, in the order you'd walk a room through it.

Scope note: this covers only work committed **after** last Friday (Aug 28). The underlying data engine it builds on was already in place before that — what's new this week is that it became visible, usable, and correct throughout the app.

Two threads landed this week:
1. **Surfacing the data layer** — the trust/dossier/radar/curation engine went from "exists in the database" to "usable on screen," plus one real should-cost correctness fix.
2. **Brand polish** — the app's logo now matches the marketing site exactly, sign-in persists between them, and a couple of SEO/color fixes.

---

## Part 1 — Surfacing the data layer

### Step 1 — Go to **Formulas**

Open any catalog formula and look at its recipe/coverage table.

**What to say:** *"Each recipe line now shows a trust-grade badge — High / Medium / Low / Blocked / Unrated — replacing an old confidence badge that had gone dead (the source data stopped sending that field, so it was quietly always blank). This is the first thing this week's work fixed: the badge you see is now backed by a real, current signal again."*

### Step 2 — Go to **Indexes** → open any commodity's detail popup

**What to say:** *"The drill-in popup gets three new panels this week: a volatility read, a seasonality chart, and a dossier — for the same series, in one screen."*

Point out specifics:
- *"The seasonality chart and its written summary come from the exact same twelve numbers — so the text and the chart can never disagree with each other."*
- *"A volatility score always names which calibration produced it and when — never just a bare number you have to take on faith."*
- *"Where a producer's market share isn't disclosed, we say 'not disclosed' — we don't quietly show 0%, which would be misleading."*
- *"If the data isn't there for a given series, the panel says so plainly instead of drawing a flat, fake-looking line."*

Then open the toolbar's **Resolution** button (super-admin).

**What to say:** *"This is a new window into data quality across the whole catalog — three tabs: Concentration (which single commodities is too much of our catalog secretly riding on), Unpriceable (recipes we can't currently price and why), and a Swap Backlog (a ranked list of which data feeds would fix the most recipes if we bought them). This existed as a queryable capability before; this week it became something a person can actually open and use."*

### Step 3 — Go to **Monitor** → toggle to **Radar**

**What to say:** *"Monitor now has a Drift/Radar switch. Drift is the existing should-cost-vs-actual table, untouched. Radar is new: it groups negotiation opportunities by what's actually driving them, sorted by how soon each one closes, and includes a 'Run radar' button, a coverage report, and market-signal alerts — all backed by the trigger-radar engine, now with an actual screen."*

### Step 4 — Go to **Contracts** (account menu, permission-gated)

**What to say:** *"There was no page for this at all before — contracts and their clauses had a backend but no UI. This week's radar screen needed something real to work against, so we built the page: record a contract's terms and notice deadline against a product, and the radar picks it up automatically."*

### Step 5 — Go to **Curation** (account menu)

Three tabs: **Trust**, **Editorial**, **Dimensions**.

**What to say:** *"This is a genuinely new screen — three separate review queues that existed as APIs with no consumer got consolidated into one console. Trust shows recipes flagged for review, worst first. Editorial is written content (outlooks, notes) pending approval. Dimensions is unresolved data-tagging decisions waiting on a person. This is the one place the underlying data actually gets better over time instead of just sitting there."*

### Step 6 — Go to **Dimensions** (top-level page)

Click the **Producers** tab.

**What to say:** *"New faceted explorer — browse the catalog by non-price facts like industry or compliance exposure — plus a producer directory tab. No backend change was needed for this; the API was already shaped correctly, we just built the screen for it."*

Mention, don't demo: *"We also ran a cleanup pass on this data — some tags had lost their audit trail from an earlier data load and were flagged as 'orphaned.' We fixed them carefully: one mis-tagged group ('Adhesives & Sealants') had 143 wrong entries; that's now down to 2 genuine ones, and nothing else in the catalog was touched."*

### Step 7 — Go to **Intelligence**

**What to say:** *"The library view changed shape this week — tiles used to be per cost-model, which meant it could only show a team's own priced products. Now tiles are per formula-and-region, so the whole platform catalog is browsable as intelligence content, not just what one team has already built. It also got faster — one request per page of 50 tiles instead of one request per tile."*

### Step 8 — The correctness fix (worth stating even without a screen to point at)

**What to say:** *"We found and fixed a real bug: the should-cost engine was only checking quarterly price history, but three-quarters of our newer commodity data only comes in monthly. That meant most of the catalog's cost recipes were silently riding flat — no price movement at all — everywhere: should-cost figures, evolution charts, negotiation briefs, squeeze calculations. Fixed by having the engine check both. 48 additional commodities now show real, live price movement that were completely flat before."*

## Part 2 — Brand & polish

### Step 1 — Compare the app's logo (in the navbar) to the one on costadvisor.org

**What to say:** *"We replaced the app's logo with a single shared source file, so it only ever needs updating in one place — and this week we made the app's navbar version match the marketing site's exactly: same size, same rounded corners, same shadow, same spacing to the text next to it. It used to look like a thinner, slightly different mark."*

Also point out: *"The image itself got compressed 92KB down to 11KB with no visible quality loss — small thing, but it's one more thing loading faster on every page."*

### Step 2 — Click the logo in the app

**What to say:** *"Clicking the logo now takes you to the marketing website instead of just refreshing the dashboard. And it's a two-way street: if you were already logged in and land back on the marketing site, it silently recognizes your session and shows a direct link back into the app instead of forcing you to sign in with Google again."*

### Step 3 — Point out the marketing site's color palette

**What to say:** *"We fixed a color problem where two of our theme colors were basically the same shade of green, so the page read as flat and monochrome. We pulled our actual parent-company brand color and gave the page genuine two-tone contrast — while every color choice still passes accessibility contrast standards."*

### Step 4 — Mention, don't demo: SEO cleanup

**What to say:** *"Google had indexed our internal app pages and our API as if they were public marketing pages. We told search engines explicitly to stay out of both, so only the real marketing site shows up in search results going forward."*
