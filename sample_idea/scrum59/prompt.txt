Wave 2 built the shape but the tables are empty, and an empty catalog cant show a buyer a single real number — so first we get the families and the 158 index feeds actually loaded. Same idea as the rest of the seed: the source keeps getting better, so this is something we rerun as improved data lands rather than a one-shot. The one extra thing worth doing up front is a sanity check — if a formula reaches for an index we dont actually have, we want that to shout at us now, not quietly turn into a product that cant be priced later on.

The idea: a loader we can run again and again as better data lands, that updates rows in place instead of piling up duplicates (upsert by a stable key). This first one covers the taxonomy and the indexes; the weighted formula components come in SEED-2.

Stable keys, so re-runs line up: family name · family+subfamily · subfamily+product · index code · formula_id.

A few things worth knowing:

Seed order matters: the combinations file is the source of truth, so load it first, then regenerate master + tier-lookup from it (rather than loading those directly).

The source filenames sometimes carry a (1) suffix from the handoff — worth tolerating that rather than tripping on it.

index_list.html is the old, retired list (139 rows, and it has an orphan IDX-CPO-CN that exists nowhere else) — skip it; the live list is the 158 in db_index_feeds.

Before importing, it's worth join-validating the ~148 index codes the combos reference against the 158 feeds, so a bad reference surfaces as a clear error instead of a silent gap. A dry-run + diff report makes that checkable before anything's written.
