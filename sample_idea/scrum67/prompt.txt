This is the back-office for the two things that quietly decide whether a should-cost holds up: what region a price is for, and how we calculate the indexes we can only approximate. Region needs a real home because, like we said, the same product genuinely costs different money region to region — without somewhere to add and shape regions we end up pricing the whole world as one flat market. And all those common-sense approximations for the paywalled indexes have to be adjustable by a human — this is the one place an admin can open a proxied index and set exactly how its worked out. Without it, anything leaning on that index quietly goes dark, and nobody wants to defend an invoice with a number they cant explain.

Rebuild the Admin tab to the new IA, and surface two admin tools: Region management (the CRUD from DB-2) and a proxy-index calculation editor.

The proxy editor is where an admin opens a proxy index and edits exactly how it's derived — the structured proxy_logic from DB-3 (base index, operation, spread, recalibration cadence). FD-1 (SCRUM-80) then runs whatever's set here.
