"Cost-structure estimator service for combos with no usable decomposition (draft output, reviewable)"

Untouched, and still the right idea — but it needs a landing place, a grain and a definition of "good", none of which the current one-liner gives it.

Shape

A service, at formula × region combo grain, that proposes a weighted line set for a combo that has none (or has one flagged as a proportional-scaling placeholder), plus the evidence for the proposal. Not a screen, not a value written into a live recipe.

What exists to build on, and what doesn't

routers/ai.py → services/ollama.py is the only AI path in the app: prompt → Redis cache → discarded. Nothing persists, nothing is reviewed. IntelligenceDetailArea.jsx:228 already records this as the blocker. An estimator that writes to that path produces output nobody can correct or approve.

The provenance/review layer in docs/CONTENT_MODEL.md is where a proposal belongs — ai_draft provenance, distinct from imported and human_approved, and FormulaRegionCoverage already carries needs_review / reviewed_by / reviewed_at with a review endpoint at formulas.py:509. Extend that, don't start a second review state.

Two independent evidence sources exist and they check each other: the priced history (ActualPrice per cost model, fitted against candidate index series) and the drop's synthesis routes, whose feedstock labels overlap heavily with cost-line labels. Whether one, the other or both is the right basis is part of this work.

Constraints worth knowing before you design

The combos that already carry lines are the ground truth. An estimator that isn't scored against them is unfalsifiable.

Some type-codes resolve to no price series at all. A proposal that puts weight on one of those produces a recipe that still cannot be costed — the estimator has to know that and say so rather than hand back a full-looking recipe.

Margin is a line inside the 100% weight total in this catalog. A proposed set that omits it, or adds it on top, is wrong in a way that survives validation (see the margin subtask).

Acceptance criteria

A callable service takes a combo and returns a proposed weighted line set plus, per line, the candidate index and why it was chosen — never mutating the existing recipe.

A proposal is persisted as a draft with ai_draft provenance and lands in the same review state machine as seeded low-confidence combos; approving it is what makes it priceable.

Proposals for lines whose index has no usable series are returned flagged, not silently included.

A backtest run over combos that already have lines reports per-combo error against the human recipe, and the report is inspectable (a file or an endpoint, not a log line).

Re-running the estimator on the same combo does not create duplicate drafts.
