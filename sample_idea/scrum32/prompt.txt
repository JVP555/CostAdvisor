"Supplier trust & margin grading (depends on alias canonicalisation)"

Grade each supplier on how their quoting behaviour compares to the should-cost line over time — consistency, direction of drift, implied margin. GET /suppliers/benchmark (backend/app/routers/suppliers.py:98) already produces the per-supplier gap comparison this scores over, so this is a scoring and persistence layer on top of it, not a second benchmark.

Hard dependency: supplier alias canonicalisation. The drop's supplier data carries a large alias set collapsing to roughly half as many real companies, and one raw string does not always map to one entity — the drop's own canonicalizeSupplierName() splits certain ' / ' strings into two separate companies. Scored off suppliers.name as it stands, a producer that appears under several spellings gets several scores, each computed over a fragment of its own history, and none of them is that supplier's actual record.

SCRUM-77 owns the producer entity and the alias layer (producer + producer_alias + producer_region, with suppliers.producer_id as the bridge), coordinating with SUP-1 / SUP-2 in docs/WAVE3_PLAN.md W3-D. This story consumes that resolution rather than building its own, and sits after it.

Also note suppliers is team_id NOT NULL and RLS-scoped. A trust score computed inside one team's data is that team's read on a supplier, not a platform fact — decide explicitly which one this is, because it changes whether the score is shareable.

Done when

A score persists per (supplier, product or subfamily) with the inputs that produced it stored alongside it, so a disputed score can be explained rather than re-derived.

The score resolves through the canonical producer, not the raw name: two rows spelling the same producer differently contribute to one score.

Suppliers with too little price history return an explicit insufficient-data state rather than a low score.

Output is inspectable as JSON.

This story belongs with the supplier platform work (docs/WAVE3_PLAN.md W3-D), not with the content layer — reparent it when that epic exists.
