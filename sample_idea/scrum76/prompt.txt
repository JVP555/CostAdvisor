"INT-2 · Editorial block model + versioning + API"


W3-B · CON-1 + CON-2 + CON-7. Sits on docs/CONTENT_MODEL.md (schema sketch, written to be argued with) and docs/DROP_2026-07_ANALYSIS.md §5.2 (the facts under it). Read §5.2 before starting — this ticket is a summary of it, not a replacement.

What this is

The July drop landed two halves. The costing spine has a place to live. The other half — synthesis routes, supplier notes, dated outlooks, macro drivers, substitution risk, supply/demand splits, compliance detail, index narratives, market-report sections — sits in newDocsFolder/seed/raw/*.json and the build never reads any of it. Nothing in the schema can hold it.

This story is the store and the read path. It is infrastructure, not a surface. Done = a block can be created, edited into a new version, approved, and read back through the API — including the block shapes that a naive schema silently drops — and all of that is inspectable without a UI existing.

Explicitly not in scope, but hanging off this schema: the loader (CON-4), the review console (W3-I), dimensions/producers (W3-C), the staleness recompute job (CON-5). The columns those need are in the table; the jobs are not.

This is not a CMS build. There are zero HTML tags in CURATED_CONTENT / SUPPLY_DEMAND_COMPLIANCE / FUTURE_OUTLOOK — it is structured fields and short prose across the payload's block types, one row each. editorial_block + editorial_block_version covers it.

Shape, and the reasoning behind each choice

The anchor key

Content keys to formula_templates.code — the platform shell — not to products. Product is the team-scoped instance pointing at the shell via formula_template_id. Content keyed there is unreachable for any team that hasn't created that product, which on day one is nearly the whole library.

subject_code NOT NULL, template_id nullable. This pairing is the expensive one. Roughly a sixth of the content payload has no formula_templates row at all: orphan CURATED_CONTENT keys, route-only keys in SYNTHESIS_ROUTES, and GRP-* group pseudo-keys that are roll-ups rather than formulas. Under a hard FK on template_id those rows don't raise — they just aren't there afterwards, and nothing downstream can tell the difference between "never authored" and "dropped at import". Same reasoning makes commodity_id / subfamily_id convenience joins rather than identity.

Four subject types

formula | index | subfamily | family. The second namespace is real and already verified clean: INDEX_NARRATIVES and INDEX_SOURCE_META.proxy key to index slug (region usually baked into the slug), and the market-report sections key to a (family, subfamily) pair. One polymorphic subject beats three near-identical tables.

Worth knowing before you design the fork path: commodity_indexes has no team_id and no RLS policy today. Index-subject content is therefore platform-only unless somebody adds tenancy there.

subject_code for family / subfamily needs a convention pinned in this ticket — ChemicalFamily.code and Subfamily.code are both nullable and deliberately not unique across forks (a fork keeps its origin's code), so neither is usable as a bare key. The drop keys these as family + "|||" + subfamily.

region nullable = the wildcard

The dated outlooks all currently carry "*", but the consumer reads entry[region] || entry['*']. The region dimension is designed for and has to survive the load; collapsing it now means re-deriving it out of prose later.

body_text and body_json

Several block types are structured objects — routes, drivers, supply/demand splits — not prose that happens to be formatted. body_format declares which column is authoritative.

Provenance: four states, not two

imported | ai_draft | human_edited | human_approved.

The bulk import is neither AI-draft nor human-approved, so a two-state flag forces every imported row into a bucket where both readings are false — and this is not an internal marker, it drives customer-visible copy. human_edited and human_approved also have to stay distinct: approval is what clears the caveat, and an edit is not an approval.

The state-to-badge mapping belongs in this story, not in whoever builds the UI later, because the state machine and the customer claim are the same thing.

The read path — CON-7, decided before the CRUD API

One ID card pulls the whole block-type vocabulary for a subject, plus dimensions, producers, flags and supply/demand splits. Built a query per block type, that is one round trip per type per card, and the Intelligence library renders a full page of cards at once.

The card is two calls, by design. CON-7 owns the composed editorial + dimensions read. The derived payload at formula × region combo grain — series, components, cycle, seasonality, volatility, tier — is SCRUM-75 / SCRUM-134's endpoint; this story consumes it and does not re-derive any of it. W3-C (SCRUM-77) adds dimensions inside CON-7 rather than shipping a second card-shaped endpoint.

Denormalised GET /formulas/{code}/intelligence, or a materialised view refreshed on publish — either works, but the choice has to land first, because it decides whether current_version_id is sufficient or whether a published-projection table is needed, which changes the write path.

Route-namespace gotcha: formulas.py keys everything on {template_id} UUID (/{template_id}/components, /{template_id}/coverage, /{template_id}/evaluate). A {code} path segment collides with that, and the template-less keys have no UUID to fall back on — so this endpoint may want to live outside that router.

Tenancy

Platform-readable + team fork: USING (_BYPASS OR team_id IS NULL OR _MEMBER_OF) — the policy shape in tx1a2b3c4d5e_taxonomy_spine_subfamily_forking.py / rls1f2a3b4c5d_fix_rls_formula_and_custom_fx.py, not the strict-tenant shape from h8i9j0k1l2m3_enable_rls.py. team_id NULL = platform, origin_id back-links a fork, uniqueness re-scoped with partial indexes the way uq_chem_fam_platform_name / uq_chem_fam_team_name do it. A team editing a platform block forks it — the platform row must not mutate.

Platform authoring gates on has_platform_permission() (app/services/permissions.py:74) + UserPlatformRole, not team has_permission. The permission list in alembic/versions/451dfc150b30_add_rbac_and_plans.py has no content category at all, so the keys have to exist before there is anything to gate on. That migration lives here — one revision, both the content.* and dimensions.* prefixes — and W3-B, W3-C and W3-I all consume it.

Columns this story creates but does not consume

derived_from and is_stale (CON-5 recompute job), expires_at (the dated outlooks carry built-in expiry, and a large share of them were written to one vantage date), internal_note (several supplierNote values are author-to-self backlog text that would render verbatim to a customer), source_note (the payload carries no citation URLs anywhere). Cheap to add now, a migration and a backfill later.

Adjacent things that are not this

app/services/narrative.py is the negotiation-brief generator — rule-based with an Ollama enhancement path, computed per costing run. Despite the name, unrelated to the narrative layer here.

FormulaRegionCoverage.needs_review / reviewed_by / reviewed_at plus the endpoint at formulas.py:509 is the existing combo review. CON-3 extends that one; this table should not grow a competing review state.

Index seasonality and season notes are reproduced from the index values — they are a cache, and the notes are templates rendering it. index_seasonal_factor is generated by SCRUM-69 and never imported; it stays out of the block-type vocabulary.

Acceptance criteria

Migration creates editorial_block + editorial_block_version: subject_code NOT NULL, template_id nullable, region nullable, body_text + body_json + body_format, four-state provenance.

A block whose subject_code has no formula_templates row survives create → read → edit → read with template_id NULL throughout.

A subject_type='index' block with a region-baked slug stores and retrieves by slug.

An edit appends a version; the prior version is still readable by version_no and the block now points at the new one.

Approve records approver + timestamp and sets human_approved; a subsequent edit does not leave the row reading as approved.

A team member editing a platform block yields a team-owned block with origin_id set, platform row unchanged and still readable by other teams; an RLS test proves one team's forked blocks are invisible to another.

A user without the platform content-authoring permission gets 403 on platform writes.

The card read path returns every block type for a subject in one request, with a test asserting query count for one card does not grow with the number of block types present.

A fixture drawn from real records in newDocsFolder/seed/raw/ — a template-less key, a json-bodied type, a wildcard-region block, an index-slug block — round-trips through the API unchanged.

Open

subject_code convention for family / subfamily.

Whether index-subject content forks per team at all, given commodity_indexes has no tenancy.
