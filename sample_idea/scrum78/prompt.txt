"INT-4 · Expert sign-off + trust state (extend the shipped review layer)"


Where this actually stands

The persistence half shipped in Wave 2. FormulaRegionCoverage (backend/app/models/formula_template.py) already carries needs_review / reviewed_by / reviewed_at / data_confidence / coverage_tier / review_metadata; POST /formulas/{template_id}/coverage/{region}/review (backend/app/routers/formulas.py:509) flips the flag and writes an audit event; FormulaDetailModal.jsx renders the caveat and the sign-off button; seed_combos.py preserves a human sign-off across re-seeds (covered in backend/tests/test_seed_combos.py). The original AC — review state survives a refresh — is met.

What no longer holds is everything that fed it. This story is now: keep the one review state we have, replace the input that disappeared, and make the result rankable.

Re-point before planning — the build half shrank, the derivation half is new.

What changed under it

The trigger has no source. needs_review was set by data_confidence == "CONF-LOW" (seed_combos.py:456). The July catalog sheet dropped the Data confidence column, and seed_catalog.py:144 already resolves it to None. Nothing sets the flag now, so the queue is empty and the sign-off button has nothing to clear.

The state is customer-visible. newDocsFolder/intelligence_mockup (19).html:1430 renders "This formula's cost-line weights have not yet been reviewed by an in-house chemistry expert (expert_reviewed: false). Treat the should-cost index as directional pending validation." — unconditionally, for everything. Whatever this story computes becomes that caveat's source of truth, in both directions: a default that is always-true publicly caveats the whole library on day one of the content load; a default that is always-false vouches for numbers nobody looked at.

The replacement signals are structural, not a column. Trust in the July data lives in the resolution layer (type-code -> card -> series): whether a combo's inputs resolve to a series at all, whether they resolve through a proxy, and — a known defect worth handling rather than trusting — a substantial share of indexed cost lines carry a proxy_status that contradicts the proxy_status on their own type-code row, so whichever column the derivation reads, the other disagrees. Also relevant: coverage_tier now has two competing definitions (the shipped worst-retrieval-tier vocabulary vs the drop's proxy density); DROP_2026-07_ANALYSIS.md §7 item 3 rules two columns, and the derivation has to say which it reads.

Margin sits inside the 100% weight total now. Weight-closure is a different signal than when CONF-LOW meant "closed by proportional scaling".

The shape

Infrastructure, not a screen. The deliverable is a trust state you can query for any combo, an endpoint that hands the review queue to a caller, and a recompute that keeps both honest. No console — that is W3-I (docs/WAVE3_PLAN.md; no epic exists yet), and it consumes this.

Extend the existing review state. Do not add a second one. The shipped UI, the review endpoint and the seed preservation logic all write FormulaRegionCoverage; a parallel model gives two answers to "has an expert vouched for this".

Five pieces:

reviewed_by becomes a user FK. It is String(128) today and the endpoint stuffs current_user.email into it, so the record decays the moment someone changes their address. models/access_request.py:24 is the in-repo pattern (reviewed_by_id FK + the display name resolved in the schema layer). Existing values are emails, so they are migratable.

A derived trust grade, computed rather than imported, replacing data_confidence as what drives needs_review. Its inputs are the resolution layer and the weight set, and the response has to name which inputs pulled it down — an ungraded "low" tells a reviewer nothing about what to go look at. It is its own stored field under its own name: either coverage_tier column answers how well covered is this, the trust grade answers is this worth a human's time, and coverage is one input to the grade. Overloading coverage_tier with it stores an input and its own output in the same place.

Sign-off pinned to what was signed off. A re-seed currently preserves reviewed_at even when the weights and index inputs underneath moved. The sign-off should carry a fingerprint of the reviewed inputs so it returns to the queue when they change, instead of showing a stale green tick. Same mechanism as CON-5's derived_from in docs/CONTENT_MODEL.md — align them rather than inventing a second fingerprint format.

Approve separated from edit. mark_coverage_reviewed goes through _require_template_edit (formulas.py:326), which resolves to formulas.edit — so the person who authored the weights can also vouch for them. The content.* / dimensions.* keys and their migration land once, on SCRUM-76's content.* permission keys + platform authoring gate subtask. This story consumes them and moves the review endpoint onto the approve key; it does not add keys of its own.

A queue query. Coverage is only listable per template today (GET /formulas/{template_id}/coverage, formulas.py:447). W3-I's console and any triage ordering need a cross-library filter by grade and review state.

Editorial blocks get their approval on the block-version row (approved_by / approved_at, docs/CONTENT_MODEL.md) — that stays with SCRUM-76. What should be shared is the vocabulary: one constants module for the trust/provenance states, used by both, so imported / ai_draft / human_edited / human_approved and the combo grade do not drift into two spellings.

Gotchas

audit_logs.team_id is NOT NULL FK teams.id. A platform-template sign-off has no team, so formulas.py falls back to _first_team_id() — the first team the reviewer happens to belong to — and silently skips the event if they belong to none. Platform-grain sign-off should be auditable without borrowing a tenant.

uq_frc_template_region cannot hold combos that differ only by variant (DROP_2026-07_ANALYSIS.md §6 item 4). Those combos have nowhere to put review state at all. The uniqueness fix belongs with the seed/DB work, not here — but do not assume one coverage row per (template, region) forever.

The fork path (formulas.py:233-241) copies needs_review and review_metadata into a team fork and deliberately drops reviewed_by / reviewed_at. Whether a platform sign-off should carry into a fork is an open call — make it explicitly, either way.

A rule of "any proxy input => needs review" puts most of the library into the queue in one shot: proxies are a large share of the resolution layer, and some type-codes resolve to no series at all. Roughly a quarter of indexed cost weight resolves through a single series, so the flags cluster rather than spread. That is why the state needs to be graded and rankable rather than one boolean that turns on everywhere.

Depends on / feeds

The column work, the FK migration and the endpoint can land immediately. The derivation reads the three-layer resolution model from W3-A / DB-5, so it lands after that or against a stubbed resolver. The approve key comes from SCRUM-76; that migration is the only thing the permission split waits on. W3-I (docs/WAVE3_PLAN.md) consumes the queue endpoint. SCRUM-75 / SCRUM-134 consumes the stored grade for the ID-card payload and reports which inputs it was computed from — it does not recompute it, and the caveat text reads one field from this story.

Done means

The grade for any combo is queryable and its inputs are inspectable — you can ask why a combo is low and get an answer naming type-codes, not a bare enum.

The queue is answerable across the library in one call, and it re-populates itself when inputs move.

Tests cover the derivation and the invalidation, not just the endpoint round-trip.

Acceptance criteria

POST /formulas/{id}/coverage/{region}/review writes a users FK; the read path returns the reviewer's display identity, and that identity still resolves after the user changes their email.

A combo whose inputs all resolve to a real series with no proxy and a closed weight set grades at the top tier with no human action; a combo with a type-code that resolves to no series grades at the bottom and the response names the offending code(s).

The grade is stored in its own field; neither coverage_tier column is overwritten by it.

The queue endpoint returns unreviewed combos across the whole library filtered by grade — not scoped to one template_id — and is orderable by something other than region/name.

Editing a component weight on a signed-off combo, or re-seeding it with changed inputs, returns it to the queue; a re-seed that changes nothing leaves the sign-off intact (extends the existing preservation test in backend/tests/test_seed_combos.py).

A user holding only formulas.edit gets 403 from the review endpoint; a user holding the approve permission succeeds.

Signing off a platform (team_id NULL) combo produces an audit record without attributing it to an unrelated team.

Nothing reads data_confidence as the driver of needs_review any more.
