Estimate: 5 pts

A lot of the live fair-price numbers are paywalled behind big market-data subscriptions. What we can do is build common-sense approximations of them from free public data — so when a product leans on an index we cant pull directly, we estimate it instead of leaving a hole. For that to work, each index needs to carry how its approximated, how often it refreshes, and how much to trust it — an estimate is a softer signal than the real feed, and a category manager wants to know which is which.

Today: CommodityIndex is region-agnostic by design — region lives on IndexValue keyed (commodity, region, year, quarter). It already has quoted_incoterm/quoted_named_place. The 158 feeds are (index × region) pairs.

Add to the index (not the value):

access_tier (Free / Partial / Subscription), frequency (Daily / Weekly / Monthly / Quarterly / Annual / Irregular), role (feedstock / energy / fixed).

Proxy-mapping fields (the load-bearing free-data layer — without these, ~105 indexes are "accessible on paper" but produce no live number): retrieval_status (free / good_proxy / weak_proxy / blocked), free_source_name, free_source_url, proxy_logic. Optional proxy_for self-FK.

Acceptance criteria:

An index carries tier + frequency + role + retrieval_status + free-source.

The 158 feeds load against the existing (commodity, region) shape with no region duplicated onto the index.

The 2 blocked feeds (ilmenite, rutile) are marked, not dropped.
