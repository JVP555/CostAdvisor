"Team-supplied provider credentials as an index source type (fallback paths already exist)"

A team that already pays for Fastmarkets, Argus or ICIS should be able to point CostAdvisor at their own entitlement rather than living on our proxy of it. That premise still holds — the drop's access figures count effective access after proxying, so they are not evidence the paywalls went away.

What is worth knowing before scoping it:

The fallback half is built. TeamIndexSource already models per-team sourcing with source_type in manual | scrape_url | upload | fixed, GET /indexes/template emits a pre-populated CSV, POST /indexes/upload ingests it, and POST /indexes/sources/{id}/scrape-now runs a configured scrape. The override hierarchy that consumes all of it is data_resolver.resolve_index_values. The gap is the credential-backed source type, not the fallback.

There is no per-team secret storage anywhere in the backend. The only provider keys in the repo are platform-level env settings — settings.eia_api_key and settings.fred_api_key in app/config.py, read directly by app/services/scrapers/eia.py and fred.py. A team-supplied credential needs somewhere to live, an access rule, and an audit story, and none of those exist yet.

The key attaches at a grain that is about to move. TeamIndexSource is keyed (team_id, commodity_id, region). Once region is baked into the series key under DB-5, that composite stops describing anything. Sequence this after the three-layer model lands, or it gets migrated twice.

A vendor key does not unblock the type-codes that resolve to no series. Those need a source that does not exist yet, or a proxy. Worth being explicit so this story is not sold as the fix for unpriceable combos.

This stays a stretch. If it slips out of Wave 3, the credential-storage shape is still the part worth deciding early, because it constrains the tenancy model.

Done when

A team admin can register a provider credential and it is never returned in plaintext by any endpoint, including the source-list response.

A new TeamIndexSource source type resolves values through the provider adapter and those values win over scraped values in resolve_index_values, with provenance visible on the returned row.

A credential that is missing, expired or rejected degrades to the existing upload/manual path and surfaces the reason, rather than emitting nulls.

Adding, rotating and removing a credential are audit-logged.

At least one provider adapter is covered end-to-end against a recorded response.
