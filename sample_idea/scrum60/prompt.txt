Lets do scrum 60 : Formula-component seed + validation + confidence gate
This loads the actual weighted recipes — the real math behind every should-cost number. But not all of them are equally solid: 99 of the 676 are still our best guesses that nobody has verified yet. And if a category manager walks into a supplier meeting quoting a number that turns out to be a guess we made up, thats the whole thing broken — the entire point is that the number can be trusted. So the shaky ones dont get to count as fact yet: an expert reviews them first, with the reasoning behind each correction right in front of them, before anyone leans on them in a real deal.
Goal: get the 676 weighted combinations in as real formula components — and, importantly, flag the shaky rows for review instead of treating them as fact.
The order that makes sense:
1.	Pull the components out of lines_html. Right now each combination's cost lines only live as HTML inside that field, so they have to be extracted (the classes are cl-idx, idx-proxy, idx-direct, idx-fixed, wt-num). One thing worth flagging: this markup has shifted shape on us before, so it's worth having whatever we build survive the formatting changing again.
2.	Store each line — tagged direct / proxy / fixed, with its margin, keyed by formula × region.
3.	Weights should land around 100% — but heads up, the real data actually runs 99.9–110, so we want to check against a tolerance rather than an exact 100.
4.	The CONF-LOW rows (99 combos across 83 formulas) are placeholders, not verified pricing, so those load behind a review flag — they shouldn't count as authoritative yet. Worth knowing: the weight corrections are already baked into the source file, so we don't want to re-apply correction_plan_log.json — instead we load it as review metadata, each entry linked back to its combo, so the expert review has the reasoning on hand.
5.	A sanity check that the load came in complete: per-formula component counts should match formula_tier_lookup.json (n_combos), and the whole thing should total 676.
Done when:
•	All 676 combos load as components, and per-formula counts match tier-lookup.
•	Sample should-costs come out within tolerance of expected.
•	CONF-LOW rows are flagged, and the parser has tests against the current markup.
Sub-tasks:
•	Parser for lines_html (+ tests)
•	Component loader (direct/proxy/fixed + margins, keyed formula × region)
•	Weight-sum tolerance check + the tier-lookup count check
•	CONF-LOW flag + load correction_plan_log as review metadata
